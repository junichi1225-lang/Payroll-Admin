# RDRA要求分析スキル 設計ドキュメント

## 背景と目的

要求分析を RDRA の考え方で進めるための対話型スキルを作ります。利用者には PdM も含まれるため、スキルはコードや実装の話に踏み込まず、要求分析そのものに徹します。

分析結果は常に HTML でプレビューでき、対話のたびに最新状態へ自動更新されることを目指します。サマリは表、具体的な内容はネストした箇条書き、業務は Mermaid のイベントモデリング図で表現します。

## スコープ

RDRA の標準要素のうち、次をカバーします。

- アクター・外部システムの洗い出し（システムコンテキスト）
- 領域（コンテキスト）の一覧
- 業務一覧と、各業務で発生するイベント・参照エンティティ・変更エンティティ
- 主要エンティティの状態モデル
- 利用シーン（バリエーション・条件を含む）

RDRA2.0 のシステム価値・外部環境・境界・システムの 4 層をすべて厳密になぞる形は採りません。PdM が扱える粒度に絞ります。

## 対話と更新のループ

スキルの中心は次の繰り返しになります。

1. Claude が分析内容を `rdra/analysis.md` に追記・修正する。Markdown を正とする
2. レンダースクリプトが `rdra/index.html` を再生成する
3. ユーザーがブラウザで開いた `index.html` が meta refresh で自動リロードされ、最新の分析がプレビューされる

最初の 1 回だけ `open rdra/index.html` を案内し、以降は対話のたびに自動で更新されます。

## プレビューの仕組み

`file://` で開いた HTML から別ファイルの Markdown を `fetch` するのはブラウザの CORS 制約でブロックされます。サーバを立てずにプレビューを成立させるため、毎ターン `index.html` 自体を再生成し、その中に Markdown を埋め込む方式にします。

- `scripts/render.mjs` は Node の標準機能だけで動き、npm 依存を持たない。`analysis.md` を読み、テンプレート HTML の `<script type="text/markdown">` に内容を埋め込んで `index.html` を書き出す
- ブラウザ側で marked.js が Markdown を HTML へ、mermaid.js が図を描画する。どちらも CDN から読み込む
- `<meta http-equiv="refresh" content="2">` で自動リロードする

Claude は毎ターン `analysis.md` を小さく編集し、`node render.mjs` を実行するだけで済みます。HTML 全文を書き直さないため、対話を重ねてもトークン消費を抑えられます。

CDN を使うためプレビューにはネットワーク接続が要ります。オフライン運用が必要になった場合は marked.js と mermaid.js をスキルに同梱する形へ後から切り替えられます。

## 分析ドキュメントの構成

`rdra/analysis.md` の章立ては次のとおりです。

1. アクター・外部システム。サマリは表、各アクターと外部システムの詳細はネストした箇条書き
2. 領域（コンテキスト）一覧。表と、各領域の説明
3. 業務一覧。領域ごとに業務を並べ、各業務に発生するイベント・参照エンティティ・変更エンティティをネストした箇条書きで記す。あわせて Mermaid のイベントモデリング図で表現する
4. 状態モデル。主要エンティティのライフサイクルを Mermaid の `stateDiagram-v2` で表す
5. 利用シーン。バリエーションと条件を含むシーンを、表とネストした箇条書きで記す

## Mermaid の記法規約

業務のイベントモデリング図はイベントストーミングの流儀に沿い、`flowchart` で次の役割を色分けして表します。

- アクター: 黄
- コマンド: 青
- ドメインイベント: 橙
- エンティティ・集約: 薄黄

`classDef` で役割ごとの色を定義し、図の見た目を全業務で揃えます。状態モデルは `stateDiagram-v2` を使います。

## モード

- 作成・更新を一体で運用する。対話で要素を洗い出し、聞き取りながら `analysis.md` を育てる。これが主役になる
- レビュー。抜け漏れと整合性を検査する。たとえばイベントに対応する業務があるか、エンティティの変更主体が存在するか、領域に業務が紐づいているかを確認して指摘する

## ファイル構成

スキル本体は `.claude/skills/rdra-analysis/` に置きます。

```
.claude/skills/rdra-analysis/
├── SKILL.md                      # トリガー・モード・対話の進め方・コードに踏み込まない方針
├── references/
│   ├── rdra-method.md            # RDRA の考え方と各要素の定義・聞き取りのコツ
│   ├── mermaid-conventions.md    # イベントモデリング図・状態遷移図の記法と色分け規約
│   └── markdown-template.md      # analysis.md の雛形（章立て）
├── scripts/
│   └── render.mjs                # analysis.md から index.html を生成する
└── assets/
    └── template.html             # 自己完結 HTML テンプレート（meta refresh / marked / mermaid）
```

成果物は利用先プロジェクトの `rdra/` に出力します。`analysis.md` と、生成物の `index.html` が並びます。

## 設計上の論点

- プレビューはサーバなしの自動リロードを優先し、毎ターンの HTML 再生成で実現する。CORS 制約を避けるための判断
- Markdown を正とすることで、PdM は HTML を見るだけで済み、差分は Git で追える
- スコープは PdM が扱える粒度へ意図的に絞り、RDRA2.0 の全層は採らない
