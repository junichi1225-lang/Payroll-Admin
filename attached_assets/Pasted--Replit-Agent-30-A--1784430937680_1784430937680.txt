### 1-2. 月60時間超の割増判定が職場横断で機能しない

**ファイル**: `timeEngine.ts:295-306`（`computeHourlyGross`）

**現状**:
```typescript
for (const [id, buckets] of Object.entries(bucketsByWorkplace)) {
  sum += parseRate(rates[id]) * bucketPaidHours(buckets); // ← 職場ごとに独立判定
}
```
職場Aで30h残業＋職場Bで30h残業＝合計60hでも、各30hが60h未満なので1.25倍のまま。
労基法は「同一の使用者に対する月内法定外残業の合計」で60h超を判定すべき。

**修正方針**:
```typescript
// Step1: 全職場の法定外残業時間を月単位で合算する
const totalOvertimeMinutesThisMonth = Object.values(bucketsByWorkplace)
  .flatMap((buckets) => buckets)
  .reduce((sum, b) => sum + b.overtimeMinutes, 0);

// Step2: 60時間（=3600分）を超えた「時間」だけ1.5倍に差し替える
// 職場をまたいで発生した残業のうち、どの職場の分から60h超として扱うかは
// 「時系列順（発生順）」で割り当てるのが素直な実装。
function splitOvertimeAcrossWorkplaces(
  bucketsByWorkplace: Record<string, Bucket[]>,
  monthlyOvertimeThresholdMinutes = 60 * 60
): Record<string, { under60h: number; over60h: number }> {
  // 日付順にソートしてから累積し、閾値をまたぐ職場でオーバーフロー分を切り出す
  const allEntries = Object.entries(bucketsByWorkplace)
    .flatMap(([workplaceId, buckets]) =>
      buckets.map((b) => ({ workplaceId, date: b.date, minutes: b.overtimeMinutes }))
    )
    .sort((a, b) => a.date.localeCompare(b.date));

  const result: Record<string, { under60h: number; over60h: number }> = {};
  let cumulative = 0;

  for (const entry of allEntries) {
    result[entry.workplaceId] ??= { under60h: 0, over60h: 0 };
    const remainingUnder60 = Math.max(0, monthlyOvertimeThresholdMinutes - cumulative);
    const under60Part = Math.min(entry.minutes, remainingUnder60);
    const over60Part = entry.minutes - under60Part;

    result[entry.workplaceId].under60h += under60Part;
    result[entry.workplaceId].over60h += over60Part;
    cumulative += entry.minutes;
  }

  return result;
}
```
この関数を`computeHourlyGross`に組み込み、`over60h`分だけ1.5倍（深夜込みなら1.75倍）の
レートを掛けるように差し替える。同一の派遣元（テナント）配下の全職場を対象に合算すること。

### 1-3. OCRエラー行で朝残業が異常計算される

**ファイル**: `timeEngine.ts:97-99`

**現状**:
```typescript
const earlyMin = earlyOvertime
  ? Math.max(0, toMin(stdStart) - toMin(ocrStart))
  : 0;
// toMin("--:--") = -1 なので toMin("09:00") - (-1) = 541分（異常値）
```

**修正方針**:
```typescript
const earlyMin = earlyOvertime && ocrStart !== "--:--" && toMin(ocrStart) >= 0
  ? Math.max(0, toMin(stdStart) - toMin(ocrStart))
  : 0;
```
根本的には `toMin()` 自体が不正入力（`"--:--"`）に対して `-1` という
「あたかも正常値のような」値を返すのが良くない設計なので、
`toMin()` の戻り値を `number | null` にして呼び出し側で明示的にハンドリングする方が安全:
```typescript
function toMin(time: string): number | null {
  if (time === "--:--" || !time) return null;
  const [h, m] = time.split(":").map(Number);
  return h * 60 + m;
}
```

### 1-4. 賞与の都道府県選択ロジックが月次と不整合

**ファイル**: `bonusCalc.ts:42-45` vs `payrollInputs.ts:154-163`

**現状**:
- 月次：実働時間が最長の職場の都道府県を採用
- 賞与：`DEFAULT_WP_KEY`（w1）固定

**修正方針**: 賞与計算でも月次と同じロジック（実働時間最長の職場、なければ
直近の月次確定データの職場）を参照する共通関数に切り出す。
```typescript
// shared/resolvePrimaryWorkplace.ts として切り出し、月次・賞与の両方から呼ぶ
function resolvePrimaryWorkplacePrefecture(
  employeeId: string,
  periodBuckets: Record<string, Bucket[]>
): string {
  let maxHours = -1;
  let primaryWorkplaceId = DEFAULT_WP_KEY;
  for (const [workplaceId, buckets] of Object.entries(periodBuckets)) {
    const hours = buckets.reduce((sum, b) => sum + b.paidMinutes, 0);
    if (hours > maxHours) {
      maxHours = hours;
      primaryWorkplaceId = workplaceId;
    }
  }
  return getWorkplace(primaryWorkplaceId).prefecture;
}
```

### 2-1. 健保料率マスタが10都道府県のみ

**ファイル**: `constants/rates.ts`（`HEALTH_R7`/`HEALTH_R8`）

職場マスタのUIでは47都道府県選べるのに、料率マスタは10都道府県しかなく、
残り37都道府県は `FALLBACK_INSURANCE_RATE.healthInsuranceRate = 0.1000`（10%）が

**修正方針**:
1. 協会けんぽの令和8年度都道府県別保険料率表（下記URL）から47都道府県分のデータを取得し、
   `HEALTH_R8`（および`HEALTH_R7`）を47都道府県フルで埋める。
   https://www.kyoukaikenpo.or.jp/about/business/insurance_rate/premium_prefectures/r08/
2. フォールバック値を残す場合も、サイレント適用ではなく「未設定の都道府県です」という
   警告をUI・計算結果の両方に出すようにする（黙って10%を使わない）。

### 2-3. 週40時間超の法定外残業が未判定

**ファイル**: `timeEngine.ts:110-112`

**現状**:
```typescript
buckets.basic = Math.min(8 * 60, remaining) / 60;
buckets.overtime = Math.max(0, remaining - 8 * 60) / 60;
```

## そのほかの自己完結型の軽微な修正（まとめて対応可）

### computeHourlyGross の端数処理（Math.round）

**ファイル**: `timeEngine.ts:305`
```typescript
return Math.round(sum); // 四捨五入
```
他の端数処理ルール（社保→50銭ルール、所得税→切り捨て or 10円未満四捨五入）と
整合しているか要確認。総支給額の端数処理として四捨五入で問題なければこのままでよいが、
方針をコードコメントで明記しておく。

### ビット演算 `| 0` の置き換え

**ファイル**: `timeEngine.ts:94`
```typescript
const grossMin = (calcHours(effectiveStart, effectiveEnd) * 60) | 0;
```
`| 0` は負の数で `Math.floor` と挙動が異なる（`-1.5 | 0` は `-1`、`Math.floor(-1.5)` は `-2`）。
不正な打刻で負値が返るケースの安全性のため、明示的に置き換える：
```typescript
const grossMin = Math.floor(calcHours(effectiveStart, effectiveEnd) * 60);
```

### 賞与特例1の二重切り捨て

**ファイル**: `bonusTaxCalculator.ts:108-109`
```typescript
const monthly = calculateIncomeTax(Math.floor(bonusAfterSI / BONUS_PERIOD_MONTHS));
return { incomeTax: monthly * BONUS_PERIOD_MONTHS, ... };
```
国税庁規定の手順は「(賞与-社保)÷6の円未満切捨て→月額表→×6」。
`calculateIncomeTax`内部でも切り捨て（甲欄なら10円未満四捨五入）を行っているため、
二重処理になっている。実害は軽微（数円のズレの可能性）だが、
`Math.floor(bonusAfterSI / BONUS_PERIOD_MONTHS)` を渡す前に切り捨てず、
内部の丸めだけに任せる形に統一する。
