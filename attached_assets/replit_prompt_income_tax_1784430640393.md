# Replit Agent 向け作業指示：所得税（源泉徴収）モジュールの置き換え

## 背景

現在 `payroll-core` 内に実装されている所得税計算ロジックを、
添付の `incomeTax.ts`（令和8年分・甲欄の電算機計算の特例に完全準拠、
国税庁公表の計算例3件で検証済み）に置き換えたい。

## やってほしいこと

1. 添付の `incomeTax.ts` を `payroll-core/incomeTax.ts` として配置する。
2. `payroll-core/index.ts` 内で所得税を計算している既存箇所
   （`calculateIncomeTax` 呼び出し・`floorYen` の二重適用箇所を含む）を、
   新しい `incomeTax.ts` の `calculateIncomeTax()` を呼ぶ形に置き換える。
   - **重要**：新モジュールは甲欄について既に「10円未満四捨五入」を内部で行っているため、
     呼び出し側で `floorYen()` を重ねて適用しないこと（既存コードにある冗長な二重適用を削除する）。
3. `dummy-data.ts` の `isCommuteAllowance`（手当名に「通勤」を含むかどうかで
   全額非課税判定している箇所）を撤去し、代わりに手当ごとに
   「課税額」「非課税額」を分けて入力・保持する構造に変更する。
   - 非課税額の上限判定（距離・手段別テーブル等）はシステム側では行わない。
     ユーザーが入力した非課税額をそのまま `nonTaxableCommutingAllowance` として
     `incomeTax.ts` に渡すだけでよい。
   - 併せて、雇用保険料の計算基礎（`gross`）には従来通り非課税分も含めること
     （所得税の非課税判定とは別枠）。既存コードのコメントに
     「賃金総額・非課税通勤手当を含む」とある通りで変更不要。
4. 甲欄／乙欄の判定は既存の社員マスタの自己申告フィールドをそのまま使う。
   乙欄で `amountAfterSocialInsurance >= 105,000円` のケースは
   `incomeTax.ts` 内で意図的に例外を投げる実装にしてあるので、
   呼び出し側でこの例外をキャッチし、画面上に
   「乙欄・105,000円以上のケースは現バージョン未対応」といった
   分かりやすいエラー表示を出すようにしてほしい（サイレントに落とさない）。
5. `PayrollResult` の確定スナップショットに、以下の項目を保存するフィールドを追加する
   （将来の税額表マスタ改定後も、過去の確定給与の内訳を再現できるようにするため）。
   - 適用した税額表年度（`taxYear`）
   - 甲欄／乙欄の区分
   - 計算時点の源泉控除対象親族数（V1は常に0でよい）

## テスト

`incomeTax.ts` の末尾に、国税庁公表の計算例3件＋V1想定例＋乙欄の暫定例、
計5件の自己検証テストが入っている（`npx tsx incomeTax.ts` で実行可能、全件成功確認済み）。
これを Vitest / Jest 等、既存のテスト基盤に移植し、CIで回るようにしてほしい。

## スコープ外（今回は着手しない）

- 乙欄の105,000円以上の帯（月額表・乙欄の階級テーブルのマスタ投入が必要。別タスク）
- 源泉控除対象親族の詳細な数え方（配偶者・障害者・ひとり親等の加算ロジック）
- 賞与の源泉徴収（別トランザクションとして別途対応予定）
