0. 目的

ハードコードされた法定料率の 誤り・陳腐化を修正 し、全料率を単一の effectiveFrom 付きテーブルに統合して対象年月で解決できるようにする。
二重化している給与計算ロジック（PayrollTab の精緻版 と payrollCalc.ts の簡易版）を 単一の純粋関数（calc-core）に統合 し、両タブが同じ計算を使うようにする。
手当の課税区分と端数処理を正しく扱う。
SPEC.md を上記の変更に合わせて更新する。

現状 constants/rates.ts の社保料率のみ effectiveFrom を持ち、雇用保険・支援金などはコード各所のリテラルで散在している。全法定料率を1つの effectiveFrom 付きテーブルに集約 し、対象年月で解決する形にする。

既存値からの主な修正点（重要）

健康保険（県別）について

現行コードに収録済みの 10都府県 を対象に、令和7・令和8の 両年度 の県別料率を協会けんぽ公式「都道府県単位保険料率」から転記する。
値を確実に取得できない場合は、勝手に概算値を入れず、その旨を報告してユーザーに確定値を確認すること。 給与の法定控除額に直結するため、推測値の混入は不可。
未収録県のフォールバック（全国平均）は残してよいが、フォールバック使用時は calc-core の出力に isApproxRate: true 相当のフラグを立て、UI で「概算」と分かるようにする。

適用開始日の扱い

健保・介護：協会けんぽは「3月分（4月納付）」改定。対象年月の月初基準で、その年の3月以降を新年度として解決する。
雇用保険：4月改定。
子育て支援金：令和8年4月分から。


4. 計算ロジックの単一化（calc-core）★最重要
PayrollTab の精緻計算（5区分労働時間・職場別・手当込み）と payrollCalc.ts の computeMonthSummary()（簡易版）が別ロジックになっており、給与確定タブに手当が反映されない・65歳判定が簡易版で欠落する等の不整合が起きている。正本を1本に統合する。

lib/payroll-core（命名は任意）に 純粋関数 computePayroll(input): PayrollComputation を新設する。

副作用なし：localStorage.getItem() の直接参照を排除し、必要なデータはすべて引数で受け取る（現状 payrollCalc.ts がフック外で localStorage を直参照している問題も解消）。
入力：従業員マスタ、契約、職場マスタ、当月タイムカード行、手当配列、対象年月、解決済み料率（または内部で resolveRates を呼ぶ）。
出力：実働区分集計（基本／時間外／朝残業／深夜／休日[法定・所定]）、支給内訳（基本給＋手当、課税／非課税の内訳）、控除内訳（健保・介護・厚年・子育て支援金・雇用保険・所得税・住民税）、総支給・総控除・差引（端数処理済み）、isApproxRate 等のフラグ。


PayrollTab（表示・編集）と PayrollFinalizationTab（確定スナップショット）は 両方この関数を使う。PayrollResult には computePayroll の出力を保存する。
既存の taxCalculator.ts / insurance.ts は calc-core から呼ぶ純粋ヘルパとして残してよい。重複している計算は calc-core に集約する。
割増賃金の倍率（時間外1.25／深夜+0.25／法定休日1.35／月60時間超1.50 など）が calc-core 内で明示的に適用されているか確認し、PayrollTab の既存挙動を正とする。簡易版にしかなかった分岐は精緻版に寄せる。


5. 手当の課税区分

AllowanceItem に taxable: boolean を追加（true=課税、false=非課税）。
プリセット7種にデフォルト課税区分を設定（通勤手当=非課税、役職手当など他は原則課税）。
所得税の課税対象 = 総支給 − 非課税手当 − 社会保険料合計（被保険者負担）。
雇用保険の算定基礎（賃金総額）には非課税通勤手当も含める（＝総支給ベースのまま。退職金・慶弔見舞金・出張旅費等の除外対象は現状どおり扱わない範囲でよい）。
既存データ移行：taxable 未設定の手当は type から推定（通勤手当→false、他→true）。推定不能なものは安全側で true（課税）。


6. 端数処理（calc-core 内で一元適用）

健保・介護・厚年・子育て支援金の被保険者負担：円未満を「50銭以下切捨て・50銭超切上げ」。
雇用保険の被保険者負担：同じく50銭ルール。
所得税：円未満切捨て。
住民税：マスタ月額をそのまま。
総支給・総控除・差引支給：円単位。

8. 受け入れ条件（self-check）
以下の検算が一致すること（標準報酬月額 300,000 円・東京・40歳以上65歳未満・令和8年度・甲欄・扶養0人）：

厚生年金（被保険者）：300,000 × 18.30% ÷ 2 = 27,450 円
介護（被保険者・令和8）：300,000 × 1.62% ÷ 2 = 2,430 円
子育て支援金（被保険者・令和8）：300,000 × 0.23% ÷ 2 = 345 円
雇用保険（被保険者・令和8）：総支給 × 0.50%（例：総支給 320,000 → 1,600 円）
健保：転記した東京・令和8料率で算出し、50銭ルール適用後に整数になること
同一入力で PayrollTab と PayrollFinalizationTab の総支給・総控除・差引が一致すること（二系統不一致の解消）
pnpm run typecheck と既存ビルドが通ること


9. 進め方

変更が大きいので、まず 変更計画（対象ファイル一覧・段階）を提示 してから着手してよい。
段階コミット推奨：(1) 料率テーブル＋resolveRates → (2) calc-core 抽出 → (3) 両タブの呼び出し置換 → (4) 手当課税区分＋端数処理 → (5) SPEC.md。
localStorage キーの構造を変える場合は移行処理を入れ、既存データが壊れないこと。
料率の確定値が取得できない・仕様判断が要る箇所は、推測で埋めず質問すること。
